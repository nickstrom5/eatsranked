# eatsranked.com

The landing page for **Eats Ranked**: free restaurant apps, one state at a time, built from public records.
It links each state's app (today: Chicago Restaurants: Ranked for Illinois, Wisconsin Eats: Restaurants
for Wisconsin), shows a U.S. map of where we're live, explains how the apps work, and has a short
"Eating out, by the numbers" section from the Bureau of Labor Statistics.

The site is one static page served by GitHub Pages from `docs/` at <https://eatsranked.com/>.
It makes no requests to other hosts (no fonts, CDNs or analytics), sets no cookies and needs no build
step on the server: styles, script, map and chart are inline in `docs/index.html`.

```
docs/                     what GitHub Pages serves
  index.html              generated by tools/build.py (don't edit by hand)
  404.html, sitemap.xml, robots.txt, CNAME, site.webmanifest, .nojekyll, .well-known/security.txt   also written by build.py
  icons/                  each state app's icon (256x256 PNG)
  favicon.svg, favicon.ico, favicon-32.png, apple-touch-icon.png, icon-192.png, icon-512.png, og.png   from make_images.py
tools/
  site-data.json          the single source of truth: states, taglines, links, App Store status, colours, icons, BLS prices
  us-states-paths.json    state outlines (us-atlas, see Credits)
  template.html, app.js, template-404.html   the page template and its script
  build.py                site-data.json + template -> docs/
  update_prices.py        refreshes the BLS series in site-data.json, then rebuilds
  make_images.py          favicons and the 1200x630 share image
  verify.py               recomputes every number from site-data.json and checks the page
  browser_check.mjs       headless-Chrome checks (layout 360-1600 px, map keyboard/hover/tap, no outside requests)
```

`tools/site-data.json` is the canonical copy of the site data from now on. It started as a copy of the
hub's `site-data.json` (the two were identical at hand-off, including Illinois' `"region": "Chicago + Illinois"`);
edit this one, not the old hub file.

## Rebuild

```sh
python3 tools/build.py        # Python 3.9+, standard library only
python3 tools/build.py --data some.json --dry-run   # does the page build from this data? writes nothing
python3 tools/verify.py       # static checks, then serves docs/ locally and fetches every link
python3 tools/verify.py --browser   # also runs tools/browser_check.mjs (Node 22+ and Google Chrome)
```

`build.py` only moves the sitemap's `lastmod` when `index.html` actually changes. Every number on the page
(the three stats, the $20 comparison, the chart, its table and hover readout) is computed from the BLS
series in `site-data.json`; `verify.py` recomputes them independently and fails if any number on the page
isn't one of them, a year, or a number that is in `site-data.json` itself.

To look at it locally: `python3 -m http.server 8741 --directory docs` and open <http://127.0.0.1:8741/>.

## Add a state

1. Put the app icon in `docs/icons/` (256x256 PNG, e.g. `docs/icons/texas.png`).
2. Add an entry to `states` in `tools/site-data.json`:

   | field | used for |
   |---|---|
   | `abbr` | two-letter code; must match `tools/us-states-paths.json` |
   | `status` | `"live"` puts it on the page and fills it on the map; anything else counts as coming soon |
   | `app`, `tagline` | card title and text |
   | `tagline_short` | optional shorter text for the map's pop-up card |
   | `region` | optional eyebrow label (e.g. `"Chicago + Illinois"`); defaults to the state name |
   | `site`, `how` | website button; "How it works" link (left out when it's the same URL as `site`) |
   | `web_app`, `web_app_label` | optional web app link (e.g. "Search on the web") |
   | `app_store` | App Store URL once the app is approved; `null` shows "Coming soon to the App Store" (not a link) |
   | `app_store_note` | hover text on the coming-soon badge |
   | `platforms` | e.g. `"iPhone & iPad, free"` (shown as "iPhone & iPad · Free") |
   | `colors.bg`, `colors.accent`, `colors.text` | card colours; `bg` fills the state on the map, `accent` fills it in dark mode. If `accent` reads below 4.5:1 on `bg`, the card's label, button and focus ring use the nearest same-hue shade that passes (build.py prints a note); `verify.py` fails if `text` doesn't pass |
   | `icon` | path under `docs/`, e.g. `"icons/texas.png"` |

3. Run `python3 tools/build.py`, then `…/python tools/make_images.py` (so the share image shows the new icon),
   then `python3 tools/verify.py --browser`, and look at the page at phone and desktop width.

The map's icon position, the "Now in …" lines, the legend swatch, the meta description and the
JSON-LD all follow from the data; nothing else needs editing.

Each page carries a Content-Security-Policy `<meta>` that allows only its own inline scripts, by hash.
`build.py` recomputes the hashes on every build, so never edit `docs/index.html` by hand: a stale hash stops
the script (`verify.py` checks them). `docs/.well-known/security.txt` expires on the date in `build.py`
(`SECURITY_TXT_EXPIRES`); `verify.py` fails once it has passed, so move it on a year and rebuild.

While any live app still has `app_store: null`, the page says **On the web now** (section label, map legend,
map labels) and "Now in Illinois and Wisconsin". Once every live app has its App Store URL it switches to
**Live now** by itself. The meta description never claims the apps can be installed.

## Prices

```sh
python3 tools/update_prices.py
```

Pulls every series listed under `prices.series` from the BLS public API v1
(`https://api.bls.gov/publicAPI/v1/timeseries/data/`, one POST, the last 10 years, no key), writes them
into `site-data.json`, regenerates the source line ("through <month>. BLS did not publish <months> data.")
and rebuilds. Months BLS didn't publish (value `-`, e.g. October 2025) are kept as `null` and drawn as a
gap. It writes nothing if a series comes back empty, short, or older than what's already there, or if
the page wouldn't build from the new data (it runs `build.py --data <new file> --dry-run` first), so
`site-data.json` and `docs/index.html` never disagree.

The Chicago/Midwest/U.S. 12-month stat needs the same month a year earlier. BLS skipped October 2025, so when
the latest month is October 2026 that stat uses September 2026 (the stat names its month; `build.py` prints a
note). Everything else uses the latest month.
The keyless API allows 25 queries a day, so run it once after each monthly CPI release (around mid-month),
then `python3 tools/verify.py` and commit. `--out some.json` fetches without touching `site-data.json`.

If the copy's claims stop being true (for example restaurants no longer outpacing overall prices, or
groceries falling), the wording switches automatically ("outpacing" -> "compared with", "rose" -> "fell",
chart title) rather than stating something false.

## Images

```sh
../chi-eats/.venv/bin/python tools/make_images.py   # needs Pillow and Google Chrome
```

Draws the Eats Ranked mark (three bars, the last in the accent colour) into the favicons and renders
`og.png` (wordmark, "Restaurants, ranked state by state.", each live app's icon) with headless Chrome.

## Go live

1. Create the public repo `nickstrom5/eatsranked` and push `main`.
2. GitHub → Settings → Pages: Deploy from a branch, `main`, folder `/docs`. Custom domain `eatsranked.com`
   (already in `docs/CNAME`); once the DNS check passes, tick **Enforce HTTPS**.
3. Check: `https://eatsranked.com/` loads, `https://eatsranked.com/nope` shows the 404 page, `www` redirects,
   and a link preview (iMessage, Slack) shows `og.png`.
4. Submit `https://eatsranked.com/sitemap.xml` in Google Search Console and Bing Webmaster Tools.

When an app is approved on the App Store: set its `app_store` to the listing URL
(`https://apps.apple.com/app/id<APP_ID>`; Chicago Restaurants: Ranked is `app_store_id` 6816931379), run
`build.py` and `verify.py`, commit. The badge becomes a "Download on the App Store" link. To use Apple's
official badge artwork instead, download it from Apple's marketing tools and commit it under `docs/`
(never hotlink it). When `chicago.eatsranked.com` is live, point Illinois's `site` and `how` at it
(`future_site`).
